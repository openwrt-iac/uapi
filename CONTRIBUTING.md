# Contributing to uapi

Thanks for considering a contribution. This page covers the dev loop; the deeper
architecture / design / wire-contract docs are linked at the bottom.

## Environment

You need a Linux host with:

- `ucode`, the language runtime. Its versions are dates, and CI runs
  0.0.20250529, as Alpine ships it. Available in most distros as `ucode` or
  `libucode`. OpenWrt ships it natively.
- `make`
- `git`
- `python3`, for `make stage`, `make gate-selftest`, `make openapi-validate`
  (which also needs `pip install openapi-spec-validator`) and the integration
  tests (which also need `jsonschema`).
- For integration tests: `qemu-system-x86_64`, `openssh-client`, `curl` and
  `jq`, plus ~2 GB free disk for the OpenWrt VM image.
- For building the APK locally: the OpenWrt SDK, about 400 MB. `make stage`
  does not download it. See [Get the matching OpenWrt
  SDK](docs/packaging.md#1-get-the-matching-openwrt-sdk).

uapi does NOT need `node` or any JS toolchain. The OpenAPI spec is generated by
a ucode script, not a JS one.

## Dev loop

```sh
make test coverage       # lint, the unit suite, then the coverage gate
make openapi             # regenerate build/openapi.json from src/resources/*.uc
make stage               # stage files into build/openwrt/uapi/files/ for APK packaging
make help                # full target list
```

Run `make test coverage` before every commit. `make test` runs only the lint
suite and the unit suite. The coverage gate fails the build if direct unit-test
coverage drops below 80% of lib exports, so new helpers need a focused test.

For integration tests against a real OpenWrt VM:

```sh
make vm-setup            # one-time: downloads + verifies the OpenWrt 25.12 image
make vm-start            # boots the VM in the background
make test-integration    # runs tests/integration/*.sh against the VM
make vm-stop             # shuts the VM down
```

CI runs all of this automatically on every PR. Locally you can stop at `make
test coverage` for most changes.

## What kinds of changes are welcome

- **New curated resources.** Follow
  [`docs/adding-a-resource.md`](docs/adding-a-resource.md). The pattern is
  uniform; expect about an hour for a typical config type.
- **Schema-property additions** to existing resources (a uci option exists but
  uapi does not surface it yet).
- **Bug fixes** with a regression test that fails before the fix and passes
  after.
- **Documentation improvements**, especially anything that lowered your learning
  curve.
- **Test coverage** for code paths the existing suites miss.

For larger changes (new wire features, new endpoints, anything touching the auth
or transaction model), open an issue first so we can talk through the design.
uapi is small on purpose; not every nice idea earns its keep against the
[zero-bloat constraint](CLAUDE.md#architectural-principles-non-negotiable).

## Commit and PR rules

Three sections of [`CLAUDE.md`](CLAUDE.md) bind every contributor, human or
agent:

- [API contract](CLAUDE.md#api-contract-non-negotiable): what a wire change
  carries, and how a breaking change ships.
- [Code and documentation style](CLAUDE.md#code-and-documentation-style): the
  bar for each comment, helper and test, and the style of code, docs and
  commits.
- [Branch + PR workflow](CLAUDE.md#branch--pr-workflow): the branch, the three
  questions that each PR body answers, and the changelog entry.

In addition:

- **One-line commit subjects.** A conventional-commit prefix is fine but not
  required (`fix:`, `feat:`, `refactor:`, `docs:`, `test:`, `harden:`).
- **Tests stay green.** A PR that breaks `make test coverage` is not merged. If
  the coverage gate trips on a new helper, add a test rather than lower the
  threshold.

PRs don't need to be GPG-signed. Only release tags do, and only the maintainer
cuts those.

## Codebase tour

```
src/
  main.uc                # uhttpd-mod-ucode entry point; dispatcher
  raw.uc                 # /raw/<package>/<id> passthrough handler
  lib/                   # shared helpers (auth, transaction, errors, ids, ...)
  resources/             # one module per curated resource (firewall.rules, system, ...)
build/
  gen_openapi.uc         # OpenAPI generator (reads src/resources/*.uc + ENDPOINTS table)
  openapi.json           # generated; committed; CI gates against drift
  openwrt/uapi/          # OpenWrt package skeleton; staged from src/ by `make stage`
  sdk.sha256             # pinned OpenWrt SDK checksums (multi-arch)
cli/
  uapi-token             # CLI for token mint / list / revoke
docs/                    # operator + contributor docs (you are here)
tests/
  unit/                  # ucode unit tests; run by `make test`
  integration/           # shell + curl tests; run by `make test-integration` in QEMU
  harness.uc             # ~100-line test harness (describe / it / assert_*)
  coverage.uc            # structural test-coverage inventory
```

## Friction-points worth knowing before you start

- **[`docs/ucode-quirks.md`](docs/ucode-quirks.md).** Read this before you write
  your first patch. ucode is OpenWrt's native scripting language and looks like
  JavaScript but has surprising differences (no function hoisting, no
  `try/finally`, strings not indexable). Each item on the list has cost a debug
  round-trip on this project.
- **[`docs/concurrency.md`](docs/concurrency.md).** uapi runs inside
  `uhttpd-mod-ucode`'s fork-per-request CGI model, not a long-lived process.
  That changes what's safe to cache and what's not.
- **[`docs/architecture.md`](docs/architecture.md).** Atomic-transaction recipe,
  ETag derivation, snapshot and restore. The "why" for the design choices. The
  scope tree is in [`docs/tokens.md`](docs/tokens.md).

## Where to get help

- File an [issue](https://github.com/openwrt-iac/uapi/issues) for a bug or a
  design question. Include
  the router's OpenWrt version, the uapi version (`cat /usr/share/uapi/VERSION`,
  or the `version` field of `GET /healthz`), and the syslog excerpt around the
  failure if you have it.
- For security-sensitive reports, see [`SECURITY.md`](SECURITY.md).
